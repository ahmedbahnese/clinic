# ملخص تدقيق المصدر (للمراجعة الداخلية)

## النطاق

أُجري تدقيق قراءة فقط لمستودع `ahmedbahnese/bsch` في `/home/ubuntu/bsch-original`: `app.py`, `db_compat.py`, واجهات HTML/CSS/JS، وثائق التشغيل/API، الاختبارات، scripts، Android/WebView، Windows/Electron، إعدادات CI/Render وملف SQLite Demo. المصدر يحتوي 77 ملفًا في الشجرة المحصورة عند 3 مستويات، وأفادت مراجعة الملفات المساندة بتغطية ملفات Android المتداخلة أيضًا. لم تعدّل ملفات المستودع الأصلي.

## النتائج المهمة

- قاعدة SQLite المرفقة هي Demo: 6 عيادات، 4 حسابات مستخدم افتراضية، 0 حجوزات، 0 QueueEntries، 0 AuditLogs. لن تنقل الحسابات الافتراضية، ولن تُستخدم قاعدة SQLite كتخزين تشغيل للمشروع الجديد.
- وظائف الويب الحالية تشمل الحجز العام والداخلي، متابعة الهاتف، الإيصال، إدارة المستخدمين/العيادات والخدمات والجداول والأيام الخاصة والإغلاق، التقارير/التصدير/الطباعة، الطابور والتحويل وسجل التدقيق والقوالب وسجل الرسائل والمزامنة.
- المصدر يحتوي مشكلات لا ينبغي نقلها: كلمات مرور افتراضية، متابعة بالهاتف فقط، كشف محتوى الإيصال/الحجز، شاشة queue public، CORS مفتوح للمزامنة، رمز مزامنة ثابت، اختلاف ترقيم الأيام، تحقق سعة غير ذري/غير موحد.
- شاشة TV موجودة كدالة غير موصولة بالتوجيه؛ لذلك لا تُعاد كصفحة نداء عامة وفق شرط المستخدم، مع بقاء عمليات الطابور الداخلية.
- قوالب الرسائل وسجلات الوارد/الصادر موجودة، لكن لا يثبت المصدر ناقل إرسال فعلي. لا يُفعّل إرسال خارجي أو مزود AI تلقائيًا.
- ملفات Android وWindows تشمل Offline/مزامنة محلية؛ يتجه المشروع الجديد إلى Supabase مركزية. أي مسودات Offline مستقبلية يجب أن تظل معلّقة حتى قبول الخادم ولا تعد بديلًا عن البيانات المركزية.

## بيانات البذرة

المصدر يصف أيام العمل بأرقام متضاربة بين JavaScript وFlask، لذا تعتمد النسخة الجديدة الأسماء الواردة في مواصفات المستخدم، وتخزن أيام ISO (`1=الإثنين` إلى `7=الأحد`). السعة المعتمدة حد إجمالي للعيادة وحد فرعي للخدمة؛ لا تجمع الحدود فوق بعضها. تعليمات الإيكو والسمعيات تنقل حرفيًا من مصدر Demo، ولا تُنشأ نصائح طبية جديدة. قبل seed، يجب مراجعة كل نص تعليمات واسم خدمة وحقل مع الجدول الأصلي؛ لا تستورد Users أو Bookings أو بيانات تشغيل.

## مراجع المصدر المؤكدة

- المستودع الأصلي الذي حدده المستخدم: [github.com/ahmedbahnese/bsch](https://github.com/ahmedbahnese/bsch). فُحصت نسخة محلية للقراءة فقط في `/home/ubuntu/bsch-original`.
- تعريفات العيادات والخدمات وتعليمات السمعيات الإضافية موجودة في `backend/app.py`، ويعيد تهيئة المحتوى `audio_instr` لشريحتي رسم السمع. يشمل النص المصدر شرط العمر `<5 سنوات` و`>3 شهور` واستثناء حالات التأخر العقلي أو الكلام، وملاحظات التحضير الموجودة حرفيًا في `supabase/seed.sql`.
- مواصفات التنفيذ هي الملف الذي أرفقه المستخدم `Pasted_content_11.txt`؛ تُعامل قاعدة SQLite المرفقة كـDemo فقط ولا تُنقل منها حسابات أو سجلات مرضى.
- السلوك المرصود في المصدر يضع أهلية العمر ضمن تعليمات الخدمة النصية؛ لم يُعثر على تحقق خادمي يفسر العمر النصي. النسخة الجديدة تعرض التعليمات قبل إرسال الطلب، وتبقي أي تحويل عمري آلي خارج النطاق حتى يحدده المسؤول الطبي صراحةً.
